🧠 Strategic Rationale & Analysis Insights

Why This Campaign Was Built

Logged-in users who return to the homepage represent a high-intent segment that is already past the awareness stage — yet the current homepage hero delivers an identical, generic experience to every visitor. This campaign was built to correct that mismatch: replacing a one-size-fits-all hero with two targeted experiences that acknowledge what we know about this user, reduce friction, and drive them toward the next conversion milestone (demo request or MQL creation).

Strategic Rationale by Decision

📌 Why target logged-in users specifically?

Logged-in users have already cleared the trust and awareness barrier — they created an account, which signals meaningful prior intent. When this segment returns to the homepage, a generic acquisition message is a wasted moment. Personalizing for this cohort maximizes the value of high-intent traffic without requiring any paid re-acquisition spend. The logged_in_users cookie provides a reliable, platform-native signal that resolves instantly, with no dependency on external data pipelines or ODP audience sync delays.

✅ Why the homepage hero as the intervention point?

The homepage hero is the first high-visibility element a returning user encounters. It sets intent and signals relevance within the first second of a session. Intervening here — rather than deeper in the funnel — captures the broadest possible share of returning traffic before any drop-off occurs. A single, well-targeted change at this touchpoint can compound across all downstream funnel stages.

🔀 Why two variations instead of one?

The two variations test distinct conversion levers simultaneously:

  • Variation 1 (Personalized Headline) — tests whether recognition and relevance alone are sufficient to lift engagement. If a returning user simply sees copy that acknowledges their context, does that drive action?
  • Variation 2 (Urgency Offer + Streamlined Checkout) — tests whether a concrete incentive with reduced friction is required to move lapsed subscribers. Adds a time-limited offer and removes checkout steps.

Running both simultaneously against a 50/50 split generates clean learning: we discover not just whether personalization helps, but which type of personalization drives the most meaningful lift.

⚙️ Why custom JS via Code Editor?

The homepage hero is rendered via a component that doesn't expose a native Visual Editor handle in the current project configuration. Using the Code Editor with targeted DOM selectors provides the most reliable cross-session injection without requiring a front-end deploy. It also preserves full A/B test integrity — both variations fire on the same DOM load event, ensuring no timing-based bias.

📊 Why Demo Request Started as primary metric?

Demo Request Started represents the highest-confidence conversion signal available in the event catalog for this audience. It is a direct downstream intent action — a user requesting a demo is actively raising their hand for a sales conversation, making it the clearest leading indicator of pipeline impact. MQL Created was added as a secondary metric to capture the downstream business outcome and validate that engagement lifts translate into qualified revenue opportunity — not just surface-level clicks.

Campaign Hypotheses

Hypothesis — Variation 1

If we replace the generic homepage hero headline with a personalized message that acknowledges the returning logged-in user's context, then we expect to see a statistically meaningful increase in Demo Request Started events — because relevance signals credibility and reduces the cognitive effort required to identify the next action.

Hypothesis — Variation 2

If we combine a personalized hero headline with a time-limited urgency offer and a streamlined checkout path, then we expect to see the highest lift in both Demo Request Started and MQL Created — because urgency removes the "I'll come back to this" deferral behavior that typically causes lapsed subscriber re-engagement attempts to fail.
